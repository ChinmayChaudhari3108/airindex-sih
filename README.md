# AIRINDEX — SIH26056 (Team CyberCrypt)

Real-Time Airfare Price Intelligence Platform. This is the full-stack
version, built with exactly the stack named on the "Technical Approach"
slide:

| Slide item              | This repo                                      |
|--------------------------|------------------------------------------------|
| Python (scraping + processing) | `backend/app/scraper/`, `backend/app/pipeline/` |
| Playwright / Selenium    | `backend/app/scraper/playwright_source.py` (template — see note below) |
| FastAPI (backend + REST API) | `backend/app/main.py`, `backend/app/routers/` |
| PostgreSQL (structured airfare database) | `backend/app/models.py`, SQLAlchemy |
| React / Plotly (dashboard) | `frontend/` (Vite + React + `react-plotly.js`) |

Data flow stages 1–6 from the slide map onto:
`scraper/runner.py` (discovery + extraction) → `pipeline/validate.py`
→ `pipeline/normalize.py` → `pipeline/index_engine.py` (index engine)
→ `routers/index.py` + `routers/fares.py` (output/API).

## Important note on the scraper

`playwright_source.py` is a **working template**, not a finished
scraper against a specific airline or OTA. Real fare pages change
their markup often, and each site's `robots.txt` / Terms of Service
needs to be checked before you point a scraper at it — the Feasibility
slide calls this out under "Compliance". So:

- The app runs end-to-end today using `MockFareSource`
  (`backend/app/scraper/mock_source.py`), which generates realistic
  synthetic fares. This keeps the full pipeline — extraction,
  validation, normalization, index calculation, API, dashboard —
  genuinely runnable and demoable.
- To go live: pick a specific, permitted source, confirm its
  `robots.txt` allows the pages you need, fill in the selectors in a
  subclass of `PlaywrightFareSource`, register it in
  `scraper/runner.py`'s `_active_sources()`, and set
  `AIRINDEX_USE_MOCK_SOURCE=false`.

## Quick start (Docker)

```bash
docker compose up --build
```

This starts Postgres, seeds 45 days of mock fare history, and runs the
FastAPI backend on http://localhost:8000. Then, separately, run the
frontend:

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173.

## Quick start (manual, no Docker)

```bash
# 1. Postgres — create a local database matching backend/.env.example
createdb airindex

# 2. Backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium   # only needed once you enable a real source
cp .env.example .env          # adjust DATABASE_URL if needed
python init_db.py             # creates tables + seeds 45 days of mock data
uvicorn app.main:app --reload --port 8000

# 3. Frontend (separate terminal)
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 — it talks to the API at
http://localhost:8000 (see `frontend/src/api.js`, override with a
`VITE_API_BASE_URL` env var if needed).

## Keeping data fresh

- `POST /api/v1/scrape/run` triggers one scrape + ETL pass on demand.
- `backend/app/scheduler.py` runs the same job every 6 hours
  (`python -m app.scheduler`, run as a separate process from the API).

## API surface

- `GET  /api/v1/health`
- `POST /api/v1/scrape/run`
- `GET  /api/v1/fares`
- `GET  /api/v1/index/trend`
- `GET  /api/v1/index/heatmap`
- `GET  /api/v1/index/elasticity`
- `GET  /api/v1/index/airlines`

Interactive API docs are auto-generated by FastAPI at
http://localhost:8000/docs once the backend is running.
